> 2026-09-24，由 Claude 执行，桌面版测试由用户操作。本报告只写统计，不含对话内容、图片和本机路径。设计见 [plan.md](plan.md) 第 9 节，任务见 [tasks.md](tasks.md)。

## 1. 结论

| 能力 | 我们自己的 app-server（P1-3） | Windows 桌面版（P1-4） |
|---|---|---|
| 文字对话 | 通过 | 通过 |
| 上传图片 | 通过 | 通过 |
| 生图 | 通过 | **失败**：桌面版的 Codex 版本有已知问题，上游已修复，见第 3 节 |
| 改图 | 通过 | **失败**：原因同上 |

- 代理原样转发：HTTP 请求和 WebSocket 连接都经过了它，日志只记元数据。
- 用同一个客户端对比，经过代理和直连的耗时差异淹没在网络波动里，代理没有带来可测出的额外延迟。
- 大请求也能正常转发：一个历史里有多张图片的旧任务，单次上行 10.17 MB。

## 2. 桌面版连不上本地代理：原因与修复

**现象**：第一次接入后，桌面版每个请求都报 `error sending request for url (http://127.0.0.1:17891/...)`，代理一条请求都没收到。

**原因**：
- 桌面版继承的用户环境里有 `HTTP_PROXY` 和 `HTTPS_PROXY`，但没有 `NO_PROXY`。
- Codex 默认按环境变量选择代理，所以连发往 `127.0.0.1` 的请求也交给了系统代理，而系统代理不会把请求转回本机。
- 我们一开始的自测没有复现，是因为测试终端恰好带着 `NO_PROXY`。

**修复**：
- 打开 Codex 自带的开关 `features.respect_system_proxy`（目前处于开发阶段，默认关闭；http-client 的 README 说明它会成为以后的默认做法）。打开后，Codex 先看 Windows 的代理设置。
- 代理地址改用 `localhost`。Windows 代理设置里的 `<local>` 只会让不带点的主机名直连，所以 `localhost` 能直连，`127.0.0.1` 不行。
- 代理同时监听 `127.0.0.1` 和 `::1`。

**复现与验证**：自测时去掉 `NO_PROXY`，模拟桌面版的环境：
- 用 `127.0.0.1`，失败，和桌面版一样；
- 用 `localhost` 但不开这个开关，仍然失败；
- 用 `localhost` 并打开开关，成功；
- 修复后，桌面版的对话和上传图片都能正常经过代理。

## 3. 生图、改图失败：Codex 版本问题

- 桌面版里生图和改图的请求同样到不了代理。Codex 日志里有 11 次生图、22 次改图报同样的网络错误，这两个数字都包括了自动重试。
- **原因**：桌面版自带的 `codex-cli 0.155.0-alpha.16` 里，生图扩展用的是默认的 HTTP 客户端，不遵守 `respect_system_proxy`。上游 [#47742](https://github.com/openai/codex/pull/47742)（2026-09-24 合并）修正了这一点：生图和历史笔记两个扩展改为使用配置里的客户端工厂。
- **结论**：等桌面版更新到包含 #47742 的版本后，生图和改图应该也能经过代理，届时要复测。如果想在这之前就能用，只有一个办法：用户自己在用户环境变量里加 `NO_PROXY=localhost,127.0.0.1,::1`。这属于系统层面的改动，也违背“免配置”，所以不作为产品方案。

## 4. 配置安全

- 配置工具只管理带标记的两段设置：
  - 文件顶部的 `openai_base_url`；
  - `[features]` 表里的 `respect_system_proxy`（没有这张表时，改为顶部的 `features.respect_system_proxy`）。
- 每次修改之前都会把原文件备份到本机的 `local/config-backup/`。
- **桌面版运行时也会写 `config.toml`**。这次测试期间它写入了三处：用户切换的默认模型、电脑操控用的管道名、新任务所在文件夹的信任设置。所以恢复时只能删掉我们自己的段落，绝不能用旧备份整体覆盖。
- 已核对两点：
  - 写入和恢复前后，除我们的段落外文件完全一致；
  - 测试结束后配置已恢复，文件里不留任何标记。

## 5. 其他发现

- **模型列表刷新超时**：模型列表接口的响应约 500 KB，Codex 给它的超时是 5 秒，在这台机器的网络下经常超时。Codex 自己的日志显示，接入代理之前的两天，每天就有 50–66 次，所以这不是代理造成的，Codex 会改用本地缓存的模型列表。
- **生图、改图不带任务 ID**：`images/generations` 和 `images/edits` 请求不带 `x-codex-turn-metadata`。以后如果需要按任务区分这类请求，要另想办法；不过改写只针对 `responses`，影响不大。
- **WebSocket 连接的任务归属**：WebSocket 的任务 ID 来自建连时的请求头，一条连接会被同一个任务的多轮对话复用。
