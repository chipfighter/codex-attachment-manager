# 界面 P4 报告

> 2026-09-24，由 Claude 执行。本报告只写统计和测试任务里的简短问答，不含真实对话、图片和本机路径。设计见 [plan.md](plan.md) 第 12 节，任务见 [tasks.md](tasks.md)。测试调用模型一律用 gpt-6-sol、推理强度 low。

## 1. 结论

- **面板已经嵌进 Codex**：它是 Codex 右侧侧边面板里的一个标签页“上下文素材”。用户在侧边面板的“新建标签页 → 插件和 MCP”里手动打开，不经过模型，也不花 token。
- **按用户定的 MVP 做完**：
  - 按时间顺序、按轮次列出任务历史里的图，可以滚动；
  - 显示缩略图，点开可以看大图预览；
  - 勾选后点“确定”保存，从下一条消息起生效；
  - 主题、字体和配色跟随 Codex。
- **在用户的桌面版上端到端测通**：打开面板，预览，重新勾选被取消的图，然后再提问，模型答对了这张图的内容。

## 2. 入口

- 这一版桌面版允许工具在 `_meta["openai/ui"].entrypoints` 里声明入口。声明成 `thread` 类型后，这个工具的页面就出现在侧边面板的“新建标签页 → 插件和 MCP”里。
- 用户点开后，桌面版用当前任务的编号调用这个工具，把结果交给页面。页面之后的调用也都带着这个编号，所以面板天然知道自己属于哪个任务。
- 标题栏没有给插件的入口，所以不做外挂窗口。
- 面板的入口工具是 `cam_panel`，列表里的名字取工具标题“上下文素材”，图标由插件服务提供，浅色和深色各一份。

## 3. 面板

- 每张图显示：
  - 缩略图、编号、名称；
  - 来源：用户上传、查看的图片、生成的图片或工具返回；
  - 尺寸和大小。
- 状态标签：
  - “不发送”：会换成普通占位符；
  - “由 IMG-xxx 代替”：会换成指向那张图的重复占位符；
  - “与 IMG-xxx 相同”；
  - “模型需要这张”：模型最近一次回复说了“需要 IMG-xxx”，而这张图没勾选；
  - “无法取消”：托管生图的结果。
- 改动先暂存，被改动的行用蓝点标出，底部可以撤销或确定。代理没在运行时，面板会提示取消暂时不会生效。
- 面板每 3 秒刷新一次，新一轮的图会自动出现，滚动位置保持不变。
- 开发页 `spike/scripts/panel-dev.ts` 用合成测试图，在浏览器里扮演 Codex 的侧边面板，用来截图和调试，不会出现在 Codex 里。

## 4. 桌面版实测

测试用 P3-6 那个任务：两张测试图 a.png 和 b.png，a.png 之前被取消，模型当时回复“需要 IMG-002”。

| 步骤 | 结果 |
|---|---|
| 从“插件和 MCP”打开“上下文素材” | 列出 2 张图：b.png 已勾选；a.png（IMG-002）显示“不发送”，并标出“模型需要这张”。缩略图正常，浅色主题正常 |
| 查插件服务日志和任务记录 | 面板读页面、读状态、读缩略图、定时刷新，全部是非模型调用，没有报错；任务记录里没有一条面板调用 |
| 预览 a.png，勾上它，点“确定” | 预览正常；保存成功，a.png 的取消记录清空 |
| 再问 a.png 的背景、形状和角标 | 这次请求带 2 张图，没有替换；模型回答“a.png 是白色背景，中央有一个红色正方形，右下角有一个黑色小方块。” |

这一轮走的是 HTTP。原因是 Codex 启动时，a.png 还没勾上，引擎按设计拒绝了 WebSocket 预连接，这个会话之后就一直用 HTTP。结果不受影响，重启 Codex 后会恢复 WebSocket。

## 5. 顺带修的问题

- **缩略图卡在加载中**：原来缩略图只在“滚动到可见”时才加载。页面不可见或还没绘制时，这个判断不会触发，缩略图就一直卡着。现在改为全部按顺序排队加载，看得见的优先。
- **日志太多**：面板每 3 秒刷新时都会写一行日志。现在只记录勾选变动、模型调用和出错。
