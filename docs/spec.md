# 规格：Codex 上下文素材管理器（暂名）

> 本文件是目标、范围、约束和验收标准的唯一事实来源（2026-09-24 经用户、Claude、Codex 三方确认）。
> 技术方案见 [plan.md](plan.md)，当前任务见 [tasks.md](tasks.md)。[IDEA.md](../IDEA.md) 是最初构想，已被本文件取代。

## 1. 目标

做一个开源工具，把某个 Codex 任务里出现过的素材按时间顺序列出来，让用户逐轮决定下一轮让模型看哪些。原始文件和聊天记录都留在本地、保持不变；取消勾选只影响之后发送的内容，不删除任何东西。

### 用户场景

用户先上传参考图 A，Codex 生成图片 B，用户再引用 B 要求修改。面板按时间顺序列出 A、B，以及 B 再次出现的记录，默认全部勾选。用户取消 A 和 B 的再次出现，然后继续创作：A 换成占位符，B 的再次出现换成指向 B 的占位符。之后任何一轮，用户都可以重新勾选 A，让它从下一次请求起重新进入上下文。

### 核心概念

- **出现记录**：一张图在任务历史里出现的一次，例如用户上传、工具查看、生成结果。每条都有稳定编号（例如 `IMG-004`），按在任务里第一次出现的顺序编号，之后不变。记录名称、来源、所在轮次、尺寸和内容指纹。
- **内容相同**：两条出现记录的字节完全相同，或者解码后的像素完全相同，就算内容相同，与文件名无关。缩放或重新压缩过的图不算。
- **勾选状态**：每个任务各有一套。勾选的图照常发送；取消的图在发出的请求里换成占位符。

### 免配置

用户不需要手动编辑任何文件。工具自动找到 Codex 的目录（Windows 上是 `CODEX_HOME`，没设时是 `%USERPROFILE%\.codex`），自动完成接入。每个任务（session）各有一套自己的勾选状态，互不影响。

代理跟着 Codex 一起启动、一起退出（用户 2026-09-24 确认）。只要配置指向代理，代理就必须在运行，否则 Codex 连不上。

### 选择规则

- 新出现的图默认勾选，照常发送，包括和前面内容相同的副本（用户 2026-09-24 决定）。用户没有取消任何图时，请求原样转发，Codex 的表现和没装工具时一样。
- 任何一条出现记录都可以在任何一轮取消或重新勾选，从下一次请求起生效，不换任务、不重建。取消的记录仍留在列表里。
- 取消时由工具判断用哪种占位符：本次请求里还有一条内容相同、仍在发送的记录，就用“重复”占位符指向它；没有，就用普通占位符。
- 只是看起来相似的图（例如缩放或重新压缩过）不算内容相同。
- 工具认不出的图，或者没法安全改写的请求，一律原样发送，并记下原因。只有用户明确取消的图才会被换掉。

### 占位符

- **普通占位符**：包含编号、名称、来源、所在轮次和尺寸，并说明：
  - 用户为控制上下文没有提供这张图，模型看不到它，不能猜测画面细节；
  - 回答需要这张图时，回复“需要 IMG-004”，用户可以在下一轮重新勾选；
  - 不要自己用工具去读取。
- **重复占位符**：包含编号、名称、来源、所在轮次和尺寸，说明它和哪一条（编号、名称、轮次）内容完全相同，那一条照常提供，请参考那一条。
- 占位符里不写本地路径。Codex 附在上传图片前后的路径标签，也一起换掉。
- 勾选状态不变时，占位符的文字每次都一样，不影响缓存。
- 现行措辞见 `spike/src/rewrite.ts`，用户 2026-09-24 认可；以后改措辞要重新做 P2 自测里的索要检查。

### 界面

- 位置：优先放在 Codex 对话里；做不到时，做成贴在 Codex 窗口旁、跟着窗口移动和缩放的面板。
- 按时间顺序列出出现记录，每条显示缩略图或图标、轮次、来源、大小、重复/版本关系和勾选状态。
- 提供“本轮将发送什么”预览，区分实际发送的素材、重复引用和占位符，并给出预计字节数。预览不得被说成已经发出的请求。
- 明确标出当前是“只读预览”还是“受控发送”。

### 为后续扩展预留

数据模型记录 MIME 类型和通用的文件元数据，核心命名不写死“图片”，方便以后接入其他文件类型。

## 2. 非目标

首版不做下面这些。其中前两项已确认是后续方向。

- 图片以外的文件类型，例如音频、视频、md、docx、xlsx；
- 按文件类型筛选的栏目（全选、只看某一类）和跨任务的素材库；
- 存储清理；
- macOS 和 Linux 适配；
- coding agent 场景，例如省略模型已读过的代码文件；
- 修改或删除原生 Codex 任务里已有的历史。

## 3. 硬约束

- 原始对话记录和素材文件始终只读，不修改、不移动、不删除。不直接写入 `~/.codex` 下的任何文件，只有两个例外：
  - 官方 app-server 在创建和运行任务时自己产生的正常写入；
  - 为接入本地代理，工具可以修改 `config.toml` 里由它自己管理、带标记的设置（用户 2026-09-24 授权）。改之前先备份，能一键恢复，其他设置一律不动。
- 真实数据不进仓库：从真实会话和用户素材里提取的图片、记录片段、日志和备份，只能放在本机的 `local/` 目录（已被 git 忽略），任何时候都不提交。仓库里的样例数据只能是合成的或脱敏的。
- 仓库里的文档和代码不写用户本机的具体路径（例如个人项目文件夹）。`~/.codex`、`%LOCALAPPDATA%` 这类通用位置可以写。本项目以后会开源。
- 不改写原生任务的历史记录。
- 代理只替换用户取消的图片，连同 Codex 附在它前后的路径标签；请求里的其他内容原样转发。
- 选择权永远在用户：哪些素材进入上下文，只由用户在面板里勾选决定。工具和模型都不能自动勾选或取消；模型只能按约定索要（例如回复“需要 IMG-004”），给不给由用户决定。
- 先在 Windows 上开发和测试。技术栈：TypeScript/Node。
- 交付形态：Codex 插件（skill 加本地 MCP 服务）；面板位置见第 1 节“界面”。

## 4. 验收标准

### 阶段 0：技术验证

用 IDEA.md 中 2026-09-24 做过只读检查的那个断流任务（原任务及其 fork）做样本，依次通过下面的关卡。测量方法见 plan.md。

1. **只读导入**：列出样本里全部图片出现记录，包括来源、轮次、大小和去重关系；无法识别的项单独列出。原任务应得到 10 份不同的内联图片，fork 的 4 张都能和原任务匹配；如果数字对不上，要解释原因。操作前后，原始记录和素材文件的哈希不变。
2. **可见、可续**：重建出的新任务能在 Codex 桌面版里看到、打开并继续对话；重启桌面版后仍能恢复。
3. **能继续改图**：选中的图能在下一轮用于继续修改；取消过的素材在后面的轮次重新勾选后，模型能正确使用它。
4. **未选不发送**：未勾选图片的内容既不出现在新任务的历史里，也不出现在实际请求里。
5. **请求变小**：实际请求字节数与“文字历史 + 选中图片”的估算相符（误差在 ±20% 以内），并且明显低于约 43.8 MB 的基线。
6. **占位符有效**：被问到未提供图片的画面细节时，模型不编造，而是说明未提供，并按约定方式索要。

### 代理路线 P2：按勾选改写

在同一个任务里：

1. 取消一张图后，下一次请求里不再有这张图的内容（按内容哈希核对），请求字节数相应减少。
2. 被取消的图所在位置是占位符；本次请求里有内容相同、仍在发送的记录时，是指向它的重复占位符。
3. 问到被取消的图的画面细节时，模型不编造，并按约定索要。
4. 重新勾选后，下一次请求重新带上这张图，模型能正确使用它。
5. 对话始终在同一个任务里，界面上完整可见；过程中没有报错或重连。
6. 全部勾选的任务，请求原样转发。
7. 原始记录文件只读，不被修改。

### 首版

> 以下按路线 A 写成，代理路线确定后重写。

1. 选定一个任务后，按时间顺序列出全部图片出现记录，无法识别的项单独列出。
2. 可以勾选、取消、重新勾选，并预览本轮将发送什么（实际素材、重复引用、占位符、预计字节数）。
3. 一键在新任务中继续：未勾选的图片不进入请求，选中的图可以继续修改。
4. 取消过的素材在之后任何一轮都能重新勾选并被发送。
5. 操作前后，原始记录和素材文件的哈希不变。
6. 显示操作前后的请求大小对比。
