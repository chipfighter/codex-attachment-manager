# 规格：Codex Attachment Manager（上下文素材管理器）

> 本文件是目标、范围、约束和验收标准的唯一事实来源（2026-09-24 经用户、Claude、Codex 三方确认），描述当前版本 v0.3.0，以后随版本更新。v0.4（Claude 桌面 Code 接入）正在开发、尚未发布，相关内容都标着“v0.4”；它的关卡、任务和验收步骤见 [v0.4/](v0.4/)。
> 技术方案见 [design.md](design.md)。v0.1 的开发记录（原方案、任务记录、各阶段报告、最初的构想）归档在 [history/v0.1/](history/v0.1/)，只作参考。

## 1. 目标

做一个开源工具，把某个 Codex 任务里出现过的素材按时间顺序列出来，让用户逐轮决定下一轮让模型看哪些。原始文件和聊天记录都留在本地、保持不变；取消勾选只影响之后发送的内容，不删除任何东西。

v0.4（开发中，未发布）：同样的管理也用在 Claude 桌面应用的 Code 标签页里（本地会话、官方订阅登录）。做法是把现有插件的机制逐块移植过去，不另起架构、不削减功能，只在平台逼迫的地方改（用户 2026-10-10 定）。和 Codex 不同的地方见下面“Claude Code（v0.4）”一节。

### 用户场景

用户先上传参考图 A，Codex 生成图片 B，用户再引用 B 要求修改。面板按时间顺序列出 A、B，以及 B 再次出现的记录，默认全部勾选。用户取消 A 和 B 的再次出现，然后继续创作：A 换成占位符，B 的再次出现换成指向 B 的占位符。之后任何一轮，用户都可以重新勾选 A，让它从下一次请求起重新进入上下文。

### 核心概念

- **出现记录**：一张图在任务历史里出现的一次，例如用户上传、工具查看、生成结果。每条都有稳定编号（例如 `IMG-004`），按在任务里第一次出现的顺序编号，之后不变。记录名称、来源、所在轮次、尺寸和内容指纹。
- **内容相同**：两条出现记录的字节完全相同，或者解码后的像素完全相同，就算内容相同，与文件名无关。缩放或重新压缩过的图不算。
- **勾选状态**：每个任务各有一套。勾选的图照常发送；取消的图在发出的请求里换成占位符。
- **自动选图**：每个任务各有一个开关，默认关。打开后，之前各轮的图默认不发，模型需要看哪张，就用取图工具按编号取回原图，只在这一轮提供；勾选的意思变成“固定发送”，默认都不勾，勾上的图每轮都发（v0.3，用户 2026-10-06 定：不在模型开口之前替它准备可能要的图，由它自己按编号要）。
- **来源**：每条出现记录属于一类来源：用户上传、PDF 页面、网页截图、查看的图片、工具返回、生成的图片。PDF 页面和网页截图是用户在 Codex 桌面版里给 PDF 或网页加评论时，Codex 随消息附上的截图，靠 Codex 写在图前面的固定说明认出（例如 “The next image shows PDF page 3 at the time of Comment 1.”）。PDF 页面记下页码；同一条消息只提到一个 PDF 时，再记下文件名。认不出的仍算用户上传（v0.2，用户 2026-09-29 定：只做认得准的来源）。

### 免配置

用户不需要手动编辑任何文件。工具自动找到 Codex 的目录（`CODEX_HOME`，没设时是 `~/.codex`），自动完成接入。每个任务（session）各有一套自己的勾选状态，互不影响。

代理跟着 Codex 一起启动、一起退出（用户 2026-09-24 确认）。只要配置指向代理，代理就必须在运行，否则 Codex 连不上。

### 选择规则

- 新出现的图默认勾选，照常发送，包括和前面内容相同的副本（用户 2026-09-24 决定）。用户没有取消任何图时，请求原样转发，Codex 的表现和没装工具时一样。
- 任何一条出现记录都可以在任何一轮取消或重新勾选，从下一次请求起生效，不换任务、不重建。取消的记录仍留在列表里。
- 分叉出来的任务，沿用原任务在分叉那一刻的勾选；之后两边各管各的（用户 2026-09-24 决定）。
- 取消时由工具判断用哪种占位符：本次请求里还有一条内容相同、仍在发送的记录，就用“重复”占位符指向它；没有，就用普通占位符。
- 只是看起来相似的图（例如缩放或重新压缩过）不算内容相同。
- 工具认不出的图，或者没法安全改写的请求，一律原样发送，并记下原因。只有用户明确取消的图才会被换掉。
- 自动选图开着时（v0.3）：
  - 这一轮新进来的图照常发送，包括用户刚上传的、模型这一轮查看或生成的；之前各轮的图换成占位符，上一轮刚生成的也一样；勾选的图每轮都发；工具认不出的图仍然原样发送。
  - 模型需要看被省略的图时，调用取图工具、传入编号，原图随工具结果回到这一轮；下一轮又换回占位符，还要就再取。
  - 取回的图放在这一轮末尾，不放回原来的位置：原来的占位符不变，前面的历史一个字节都不变，不影响缓存。
  - 关着时，选择规则和 v0.2 完全一样。

### 占位符

- **普通占位符**：包含编号、名称、来源、所在轮次和尺寸，一句话说明原图被用户省略以节省上下文，并提示需要时回复“需要 IMG-004”。
- **上下文管理说明**：一次请求里只要有普通占位符，就在第一张被省略的图所在那一轮的用户消息之前，插入一条开发者消息，说明：
  - 这些图在出现的那一轮真实存在，模型当时看过；之前对它们的描述和判断仍然有效，不要因为现在看不到就当成猜测，也不要收回；
  - 被问到能不能看到某张被省略的图时，如实说现在看不到（被用户省略了），之前的描述仍然有效；
  - 不要补充之前没说过的画面细节；需要时回复“需要 IMG-xxx”，用户可以重新勾选；不要自己用工具去读取；
  - 用户重新勾选的图回到它原来的位置，前面标着“已提供”，不会出现在用户的新消息里；标着“已提供”的图现在就能看到，被问到时直接看图回答，不要说看不到（v0.1-25）。
- **为什么放在开发者消息里**：用户 2026-09-25 发现，占位符放在原图的位置，模型会以为自己从没看过那张图，于是收回之前看着原图做出的正确回答。把这些说明写在占位符里也没用：占位符属于用户内容，模型不把它当成证据。改成开发者消息后，两次自测都不再收回（见 [history/v0.1/tasks.md](history/v0.1/tasks.md)）。
- **重复占位符**：包含编号、名称、来源、所在轮次和尺寸，说明它和哪一条（编号、名称、轮次）内容完全相同，那一条照常提供，请参考那一条。内容仍然看得到，不需要上面的说明。
- **“已提供”标签**：一次请求里只要有图被换掉，每张仍在发送、有编号的图前面都加一行标签，写法和占位符的第一行一样，状态是“已提供”，例如“[图片 IMG-002（[Image #2]） 已提供｜名称｜来源｜第 1 轮｜尺寸]”。原因：用户 2026-09-28 发现，重新勾选的图回到原来的位置、夹在占位符中间，而 Codex 自己的“[Image #2]”在每条消息里都从 1 开始，模型对不上编号，就说看不到。没有图被换掉时不加，请求照旧原样转发。
- 占位符里不写本地路径。Codex 附在上传图片前后的路径标签，也一起换掉。
- PDF 页面和网页截图被取消时，占位符和用户上传的图一样，来源写“用户上传”；Codex 写在图前面的那句说明原样保留，模型仍然知道那是哪一页（v0.2，用户 2026-09-29 定：不改发给模型的文字）。
- 勾选状态不变时，占位符和说明的文字、位置每次都一样，不影响缓存。
- 现行措辞见 `plugin/src/rewrite.ts`，占位符格式用户 2026-09-24 认可，说明是按用户 2026-09-25 的要求加的。以后改措辞，要按 AGENTS.md 重新跑两个自测：三个 GPT-6 模型，中文、英文（`--lang en`）各一次。
- 占位符和说明跟着界面语言：中文界面用上面这版中文，英文界面用意思相同的英文版，模型需要图时回复“need IMG-004”（用户 2026-09-25 定，避免上下文里的语言不一致）。
- 自动选图开着时（v0.3），占位符和说明换成自动选图的版本：说明这个任务开着自动选图、之前各轮的图默认省略，需要时调用取图工具按编号取回，取回的图只在这一轮提供，之前说过的内容够用时不要取；“这些图当时真实存在、之前的描述仍然有效、不要猜测或补充没说过的细节”这几点和手动版一样。

### 界面

- 位置：Codex 右侧侧边面板里的一个标签页“上下文素材”。用户在侧边面板的“新建标签页 → 插件和 MCP”里手动打开，不经过模型，也不花 token（P4 实测通过）。Codex 标题栏没有给插件的入口，所以不做外挂窗口。
- 只列这个任务历史里已有的图：用户上传的，和模型在这个任务里查看、生成的。面板不新增素材。
- 按时间顺序、按轮次列出，可以滚动。每条显示缩略图、编号、名称、来源、尺寸、大小、内容相同的关系和勾选状态；点缩略图放大预览。
- 勾选和取消（单张或整轮）点一下就保存，从下一条消息起生效；没有“确定”和“撤销”（用户 2026-09-28 定：先暂存再确认的操作感受差，也容易出错）。底栏始终显示“勾选的图片会随下一条消息发给模型”，勾选后不另外提示“已保存”（用户 2026-09-28 定）。
- 面板占满侧边面板的高度：页头和底栏固定，只有列表在中间滚动，整个面板不会被滚走（用户 2026-09-27、28 报告：点靠下的整轮勾选框后，面板只剩一条，已修复）。
- 主题、字体和配色跟随 Codex。
- 面板顶部显示下一条消息的发送预览：照常发送几张、占位几张（其中重复几张），预计请求大小和全部发送时的对比，以及上一次请求实际少发了多少。预计值以引擎记录的上一次完整请求为基准，标明是“预计”，不写成已经发出的请求。
- 上一次请求没能按勾选改写，或者取消时这一轮还在走 WebSocket，面板上都有提示；代理没在运行时也提示。
- 模型最近一次回复说了“需要 IMG-xxx”，而其中有图还没勾上时，页头显示一行“模型需要 N 张没发送的图”，列出这些编号（用户 2026-09-26 定，图多时靠它找到模型要的那张）：
  - 点编号，列表把那一行滚到正中，闪两下，键盘焦点落到它的勾选框上；
  - 勾上以后编号就从这一行消失，全部勾上后整行隐藏；
  - 这一行固定在页头，不跟着列表滚动。
- 每一轮的标题行末尾有一个勾选框，和各行的勾选框在同一列，用来整轮勾选或取消（用户 2026-09-26 定，图多时成批去掉某一轮的图）：
  - 这一轮能改的图全勾着时显示 ✓，点一下全部不发送；只勾了一部分时显示“–”，没勾的时候是空框，这两种点一下都是全部勾上；
  - 只算能改的图，“无法取消”和“已不在上下文”的不算；能改的图少于两张时不显示，因为那一行自己的勾选框就够了；
  - 和单张勾选一样，点一下就保存。
- 可以按来源筛选列表（v0.2，用户 2026-09-29 定，图多时只看某几类）：
  - 标题右侧、刷新按钮旁边有“筛选”按钮，默认收起；任务里只有一类来源时不显示。
  - 展开后，筛选栏在页头最下面、紧挨着列表：这个任务里有的每类来源一个带数量的圆角按钮。不用方框勾选框，免得和每行决定“发不发送”的勾选框混淆。
  - 可以多选：选了哪几类，就只显示这几类的全部图片；点“全部”恢复显示全部，默认是“全部”。
  - 收起后如果仍在筛选，按钮上有小点，标题旁的数字变成“显示数/总数”。
  - 筛选只影响显示，不影响发送：没显示的图照旧按自己的勾选发送，发送预览和请求大小仍按全部图计算。
  - 整轮勾选只管这一轮正在显示的图；一张都没显示的轮次整行隐藏。
  - “模型需要”提示条照旧列出全部；点到没显示的图时，自动选上它的类别，再定位到那一行。
  - 展开状态和选中的类别在面板开着时保留，关掉再打开回到默认；不写磁盘。
- 自动选图（v0.3，用户 2026-10-06 看过标注截图后定）：
  - 底栏右侧有“自动选图”开关，每个任务各开各的，默认关，点一下就保存。底栏那句说明跟着变：关着时是“勾选的图片会随下一条消息发给模型”，开着时是“勾选的图每轮都发，其余由模型按需取回”。
  - 开着时，勾选框的意思是“固定发送”，默认都不勾，和手动时的勾选分开记：关掉自动，手动时的勾选原样回来。整轮勾选就是把这一轮的图全部固定发送。模型取图不改勾选。没勾的图本来就默认不发，不再逐张标“不发送”。
  - 页头的“模型需要”提示条换成“最近一轮模型取回 N 张”，列出编号，点编号定位到那一行，用法和“模型需要”一样；模型取过的图在它那一行标“模型取回”。
  - 发送预览写“固定发送几张、占位几张”；预计请求大小只算固定发送的图，不含模型这一轮要取的（事先不知道）。
  - 模型取回的那份副本不在列表里另占一行，只在原来那一行标出来。
  - 关着时，面板和 v0.2 一样。
- 面板自动刷新：
  - 平时每 3 秒读一次；
  - 用户把鼠标移进面板、点击、滚动时立刻读一次；
  - 标题右侧有“刷新”按钮，超过 30 秒没更新时变成橙色。
- 面板左上角显示任务名，和 Codex 里的名称一致，用户改名后跟着变；没有名称时显示第一条消息的开头，还没开始的任务显示“新任务”（用户 2026-09-25 定）。
- Codex 的侧边面板按任务分开：一个标签页只属于一个任务，切到别的任务再切回来，标签页还在。所以面板不用跟随任务切换。
- 在新任务发出第一条消息之前打开的面板，发出第一条消息后自动切到这个任务（用户 2026-09-25 定，取代 v0.1-8 的“关掉再打开”）：
  - 只认用户自己开的任务，子代理、分叉和后台自动任务都不算；
  - 只认面板显示在屏幕上时开始的任务；
  - 面板显示期间开始了好几个任务时，跟最新的一个；只有两个任务几乎同时开始（相差 20 秒以内）时，才列出名称让用户点选（用户 2026-09-25 改：原来只要有两个就让用户选，而 Codex 每隔几分钟给新任务页换一个预备任务，面板会被反复询问）。
- 子代理不单独处理：带历史启动的子代理，Codex 记成从主任务分叉，按分叉的规则继承勾选。其他情况等开源后按用户反馈再定（用户 2026-09-25 定）。
- 标题右侧是“停用插件”或“启用插件”，两种样式不同。点一下立即生效，不用再确认（用户 2026-09-25 定）。
  - 停用或启用后，中间的提示说明要重启 Codex 才生效，另一个按钮随时可以撤回；
  - 撤回到 Codex 启动时的状态，就不再提示重启。
- 语言（用户 2026-09-25 定）：
  - 面板跟随 Codex 的界面语言；Codex 没告诉面板时，看系统语言。
  - 标签页标题和发给模型的说明也跟随 Codex 的界面语言，从装好起就对，不用先打开面板；切换语言后，发给模型的说明从下一条消息起就换，标签页标题要重启 Codex 才换（用户 2026-09-26 定：直接读 Codex 自己记下的语言设置，不改成默认英文）。
  - v0.1 支持简体中文和英文：任何地区的中文都显示简体中文，其他语言都显示英文。以后有用户反馈再加其他语言。
  - Codex 自己显示的名字：插件页上名称和一句话简介用英文（Codex Attachment Manager），详细说明先英文、再附一段中文，因为插件清单只能写一种文字；标签页标题跟着语言（“上下文素材”或 Context Assets）。
  - 安装命令在终端里的输出，按系统语言。
- 以上是用户 2026-09-24 定的 MVP，外加 2026-09-25 要求补上的发送预览、改写失败提示、自动刷新、这两个按钮的位置和名称、标题里的任务名、新任务的自动绑定，以及中英文界面；2026-09-26 加了“模型需要”提示条、整轮勾选，以及直接读 Codex 的语言设置；v0.2 加了 PDF 页面、网页截图两类来源和按来源筛选（用户 2026-09-29 定）；v0.3 加了自动选图（用户 2026-10-06 定）。

### Claude Code（v0.4）

开发中，尚未发布。这里只写和 Codex 不同的地方；编号、内容相同、勾选、占位符和自动选图的规则照搬。

- **范围**：Claude 桌面应用 Code 标签页里的本地会话，官方订阅登录，不需要 API key。Claude Code 的会话就相当于 Codex 的任务，每个会话各有一套勾选。已经改用别的服务地址，或者用第三方模型服务（Bedrock、Vertex、Foundry）的会话不接管。
- **接入**：装上 Claude 插件就生效，不用手动配置。插件在会话启动时，把这个 Claude Code 进程的请求地址指向本机引擎，进程结束时还原。登录凭据原样转给 Anthropic。
- **说明的位置**：Anthropic 不允许把系统消息放在用户消息之前，所以“上下文管理说明”放在第一张被省略的图所在的那条消息之后，是一条系统消息。另外，每条含被省略图片的消息后面都跟一条简短说明：这几张图当时是原图，之前的描述仍然有效；被问到要看图才能回答的细节时，写出“需要 IMG-xxx”，用户才知道该勾回哪张。Codex 的措辞不变。
- **思考记录**：思考块原样转发。改过的历史被 Anthropic 拒绝时（2026-08-31 以后注册的账号会这样），改发原始请求，面板提示这次没能按勾选改写，这一次也不算取消成功。
- **面板**：和 Codex 是同一个面板页面（用户 2026-10-10 要求两边一致）。Claude Code 不给用户打开插件的 MCP 应用，插件自己的小面板（Mod 面板）也放不进网页，所以面板由本机引擎作为网页提供：
  - 用户输入 `/cam`，面板在 Claude 桌面自带的浏览器里打开，就在对话旁边（用户 2026-10-10 选定）。
  - 只有两种情况才弹出插件的小面板：自带浏览器打不开时（终端、VS Code，或调用失败），给出面板链接和“复制链接”按钮；这个会话的请求没经过引擎、勾选不会生效时，提醒用户。
  - 新会话的第一条输入就是 `/cam` 时，输入框会提示命令不存在，但发出后照常打开：Claude 桌面要等第一条输入才启动会话的进程，插件这时才注册 `/cam`。保持现状，在用户文档里写明（用户 2026-10-10 定）。
  - 没有 Codex 特有的“启用插件 / 停用插件”按钮和新任务绑定。
  - 语言跟着插件，和发给模型的说明一致，不跟着浏览器。
- **取图工具**：模型调用 `cam_view_image` 不弹权限确认，和 Codex 版的自动批准一样；用户自己的钩子或设置拒绝、或要求询问时，照旧按它们来（用户 2026-10-10 同意）。

### 为后续扩展预留

以后接入音频时，照图片的做法：Codex 发音频的格式和图片几乎一样，见 [design.md](design.md) 第 11 节；什么时候开始做，见第 2 节。

## 2. 非目标

v0.1 到 v0.3 都不做下面这些。其中音频和其他语言已确认是后续方向。

- 图片以外的文件类型（用户 2026-09-29 查证后定）：
  - 音频：等 Codex 里有能直接听音频的模型再做。Codex 从 2026-07 起能把音频发给模型（用户附加的音频、工具返回的音频，格式和图片几乎一样），但现有的模型（GPT-6、GPT-5.6、GPT-5.5）只收文字和图片，Codex 在发送前把音频换成一句“不支持音频输入”的说明，请求里没有音频可管。开始做的条件：Codex 的模型清单（`~/.codex/models_cache.json` 里的 `input_modalities`）出现 `audio`。
  - PDF 和视频：Codex 不把这两种文件本身发给模型。模型要先把它们转成文字（抽取文本）或图片（渲染页面、抽帧）才看得到，转成的图片按普通图片管理。
  - md、docx、xlsx、代码这类能转成文字而不丢信息的文件：它们以文字进入上下文，不在管理范围内。
- 简体中文和英文以外的语言，以及面板里手动切换语言（用户 2026-09-25 定：等有用户反馈再说）；
- 整个任务一键全选或全不选，以及跨任务的素材库（用户 2026-09-26 定：成批勾选只按轮次做；全选用处不大，因为默认就是全部发送，一键全不选又容易误操作）；
- 猜模型自己渲染或抽帧的图来自哪个 PDF 或视频、按原文件归组，以及在面板里预览原来的 PDF 和视频（用户 2026-09-29 定：只做认得准的来源；原文件本身不进上下文）；
- 存储清理；
- coding agent 场景，例如省略模型已读过的代码文件；
- 修改或删除原生 Codex 任务里已有的历史；
- 在 Codex 对话里把模型要的图的编号做成可点的引用，点了打开面板或原图（用户 2026-09-26 看过调研结果后决定不做，收益不值得；原因见 [history/v0.1/plan.md](history/v0.1/plan.md) 第 18 节）。
- v0.4 也不做（用户 2026-10-10 确认的方案）：其他模型供应商、云端会话、跨会话素材库、新的常驻系统服务；也不因为换了客户端，就把原生 PDF、文档、音频、视频和普通文本文件纳入管理。

## 3. 硬约束

- 原始对话记录和素材文件始终只读，不修改、不移动、不删除。不直接写入 `~/.codex` 下的任何文件，只有四个例外：
  - 通过 Codex 自己的命令行登记插件市场、安装和卸载插件时，Codex 对 `config.toml` 和插件缓存的正常写入（P5）；
  - 官方 app-server 在创建和运行任务时自己产生的正常写入；
  - 为接入本地代理和面板服务，工具可以修改 `config.toml` 里由它自己管理、带标记的设置（用户 2026-09-24 授权）。改之前先备份，能一键恢复，其他设置一律不动。只在这些时候改：用户运行安装或卸载命令；用户在面板里点“启用”或“停用”；插件被移除或关掉、又没先停用时，引擎把 Codex 恢复直连（v0.1）；
  - 为让生图和改图也能连到本地代理，工具可以在 `~/.codex/.env` 里写一段带标记的 `NO_PROXY`，只含本机地址，并保留用户自己的条目（用户 2026-09-24 同意）。`.env` 可能含密钥，工具不复制、不输出它，只增删自己的那一段；文件里只剩这一段时，恢复时连文件一起删掉。
- v0.4：Claude Code 的会话记录（`~/.claude/projects/` 下）同样只读。工具不直接写 `~/.claude` 下的文件，Claude 插件的登记、安装和卸载都由 Claude Code 自己的插件命令完成。插件只改它所在的那个 Claude Code 进程里的 `ANTHROPIC_BASE_URL` 和 `NO_PROXY`，进程结束时还原。
- 真实数据不进仓库：从真实会话和用户素材里提取的图片、记录片段、日志和备份，只能放在本机，开发时放在 `local/` 目录（已被 git 忽略），装好的插件放在数据目录（Windows 是 `%USERPROFILE%\.codex-attachment-manager`，macOS 是 `~/Library/Application Support/codex-attachment-manager`，Linux 是 `~/.local/share/codex-attachment-manager`）；任何时候都不提交。仓库里的样例数据只能是合成的或脱敏的。Windows 的数据目录 2026-09-25 从 `%LOCALAPPDATA%` 下挪出来（用户同意）：Codex、Claude 这类微软商店应用启动的程序在 AppData 里新建的文件，会被转存到各应用的私有目录，插件服务、引擎和命令行看到的数据就不一样了。
- 仓库里的文档和代码不写用户本机的具体路径（例如个人项目文件夹）。`~/.codex`、`%LOCALAPPDATA%` 这类通用位置可以写。本项目以后会开源。
- 不改写原生任务的历史记录。
- 代理只替换用户取消的图片，连同 Codex 附在它前后的路径标签；自动选图开着时，还替换之前各轮没有固定发送的图（v0.3）。有图片被省略时，另外插入一条“上下文管理说明”开发者消息（用户 2026-09-25 要求告诉模型原因，见第 1 节“占位符”），并在仍发送的图前面加“已提供”标签（v0.1-25）。请求里的其他内容原样转发。v0.4：Claude 的请求里，说明是系统消息（位置见第 1 节“Claude Code（v0.4）”）；思考块原样转发，不删除，也不关掉思考。
- 选择权在用户：默认只由用户在面板里勾选决定，工具和模型都不能自动勾选或取消；模型只能按约定索要（例如回复“需要 IMG-004”），给不给由用户决定。用户给某个任务打开“自动选图”后，之前各轮的图默认不发，由模型用取图工具按编号取回需要的图，只在这一轮有效；模型不能改用户的勾选，也不能替用户开关自动选图（v0.3，用户 2026-10-06 定，取代原来的“选择权永远在用户”）。
- 先在 Windows 上开发和测试。技术栈：TypeScript/Node。macOS、Linux 由 CI 验证能装上、能启动；这两个平台桌面版上的实测，等用户在 GitHub 上反馈（用户 2026-09-25 定）。
- 交付形态：Codex 插件。插件带一个本地 MCP 服务，负责拉起引擎、提供面板；仓库根目录就是插件市场。面板位置见第 1 节“界面”。
  - 用户在 Codex 的插件页面添加插件市场 `chipfighter/codex-attachment-manager`、装上插件，再在面板里点“启用”；卸载前在面板里点“停用”。
  - 也可以用发布附带的一行命令安装、卸载。开发时用仓库里的 `cam install` / `cam uninstall`。
  - v0.4：同一个仓库也是 Claude 插件市场（`.claude-plugin/`）。Claude 插件带同一个 MCP 服务，另加一个 Mod，分别负责切换请求地址和 `/cam`。用户用 `claude plugin marketplace add chipfighter/codex-attachment-manager`、`claude plugin install codex-attachment-manager@codex-attachment-manager` 安装。Claude 桌面不带 Node，没装 Codex 时需要 Node 24 或更新版本（用户 2026-10-10 定：在说明里写明，不自动下载）。
- 许可证：MIT（用户 2026-09-25 确定）。

### 首版（v0.1）

## 5. 待定问题

- 在插件页面移除或关掉插件、没先在面板里停用时，代理设置还在：
  - macOS、Linux 上，引擎会发现这一点，把 Codex 恢复直连，下次启动 Codex 时生效。
